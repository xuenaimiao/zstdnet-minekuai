===== 正文开始 =====

ZstdNet 用 ZSTD 实时压缩 Minecraft 的联机流量，让同样的游戏内容只占原来几分之一的公网带宽。

【一句话介绍】

ZstdNet 在玩家和服务器之间加一层透明代理，把来回传输的游戏数据实时压缩再转发。玩家照常填服主给的那个地址进服，玩法、指令、存档一律不变，变的只有带宽账单。

【实测效果】

大型整合包「齿轮盛宴」的服务器侧实际统计：

>>> 代码块
Raw: 189.06 GB (3.6MB/s) | Zstd: 10.28 GB (252.7KB/s) | Ratio: 5.44% | Conns: 8

读法：原始游戏流量 189 GB，真正走公网的只有 10.28 GB，Ratio 5.44%（越低越省）。上行速率从 3~5 MB/s 压到 200~300 KB/s 这个量级。

收益取决于整合包和玩法：重复数据越多（机械动力系、大型整合包、大量实体的场景），省得越明显。

【谁适合用】

・机械动力（Create）系服务器
・大型整合包服务器
・走 FRP / 内网穿透 / 隧道联机、上行带宽吃紧的服务器
・家宽开服、上传只有几 Mbps 的场景
・单机「对局域网开放」后，想给朋友一个更省流量入口的房主

【它做了什么】

省带宽的几层，可以叠加：

・ZSTD 实时压缩：双向压缩转发，压缩等级 1~22 可调
・区块引用缓存 CRC（默认开启）：客户端已经收过的区块，再次下发时只发 8/16 字节的引用令牌，或者只发字节级增量；断线重连后依然有效。它工作在 ZSTD 之前，两者是叠加而不是二选一
・实体包流变换（可选）：实体/生物特别多的场景（机械动力契约体、刷怪塔、怪潮），把同类字段聚成连续列再交给 ZSTD，让跨包的重复变成能命中的长匹配
・训练字典（可选，一键全自动）：服务端自动采样在线流量、后台训练、热插启用并自动下发给玩家，不用重启、不用手动分发字典
・长距离匹配 LDM（可选）：面向「同样的大结构在几分钟内反复出现」的服务器

省心的部分：

・自动接管端口：服务端启动时读取 server.properties 里的 server-port 直接接管，后端 Minecraft 自动挪到另一个本地空闲端口。玩家继续用原来的地址和端口，不用记新端口
・内置正版验证：登录阶段让客户端在本地向 Mojang 证明账号所有权（access token 不出客户端），服务端核验后保留真实的正版 UUID 与皮肤，全程不开加密、压缩照常。离线后端也能验证正版，不用再额外装 TrueUUID（插件端暂不支持此项）
・语音模组零配置：自动探测后端 Simple Voice Chat / Plasmo Voice 监听的独立 UDP 端口并一起接管，玩家进服后客户端自动开监听；默认 tunnel 模式下语音复用入口端口，对外只需放行一个口
・同端口 UDP 透传：兼容 Sable、机械动力：航空学 这类依赖 Minecraft 同端口 UDP 的模组
・真实 IP 还原：经代理进来的玩家，在进服日志、/ban-ip 和各类按 IP 风控的插件里看到的是真实 IP，而不是 127.0.0.1
・游戏内 HUD：输入 /zstdhud 打开，直接看到当前有没有在走 zstd、实时速率、累计流量、压缩率、连接数
・原版状态查询透传：服务器列表照常 ping 得到
・没装模组的玩家不受影响：照常直连进服，只是这条连接没有压缩
・限速与防刷：单 IP 连接数、请求频率、封禁时长、单连接与全局限速都可以配

【支持的版本与平台】

mod 端：

・Forge：1.16.5、1.18.2、1.19.2、1.20.1
・NeoForge：1.20.1、1.21.1、1.21.11、26.1、26.2
・Fabric：1.19.3、1.20.1、1.20.4（同时覆盖 1.20.3）、1.21.1、1.21.11、26.1、26.2

插件端（不需要 mod 加载器）：

・Bukkit / Spigot / Paper / Purpur，以及 Arclight / Mohist / CatServer 等混合端
・一个 jar 跨 1.20.1 到最新 1.21.x / 26.x 通用，支持 Folia

版本注意：26.1 / 26.2 构建需要 Java 25；1.21.11 需要 Java 21，且只覆盖 1.21.11 本身，不兼容 1.21.9 / 1.21.10；Fabric 1.20.4 构建同时覆盖 1.20.3，但不兼容 1.20.2 与 1.20.5+。

推荐客户端和服务端装同一个版本。ZSTD 压缩天生要两端配合，只装一边不会有压缩收益。

【怎么用】

玩家：

1. 把对应版本的 ZstdNet 放进 mods/
2. 服务器地址照填服主给的那个，正常进服
3. 想确认有没有生效，游戏里输入 /zstdhud 打开 HUD 看一眼

mod 服服主（Forge / NeoForge / Fabric）：

1. 把同版本的 ZstdNet 放进服务端 mods/
2. 启动一次，会生成 config/zstdnet-server.properties，默认就是 enabled=true、auto_takeover=true
3. 完事。玩家继续连原来的端口，ZstdNet 已经接管了它
4. 如果前面还有 FRP / 反代 / 内网穿透，请确认公网入口最终转发到 ZstdNet 的 listen 端口，别直接转发到原版游戏端口，否则会绕过压缩

插件服 / 混合端服主（Paper / Spigot / Purpur / Arclight / Mohist）：

1. 把 zstdnet-bukkit 的 jar 放进 plugins/ 并启动
2. 会生成 plugins/ZstdNet/zstdnet-server.properties，默认独立监听 25566（也就是 server-port + 1）
3. 在防火墙 / 安全组放行这个端口
4. 装了 ZstdNet 客户端 mod 的玩家，把地址填成 服务器IP:25566 就享受压缩；没装的玩家继续用 25565，完全不受影响

为什么插件端要用独立端口：插件加载时 MC 服务器端口已经绑定了，插件没法像 mod 那样把后端挪走再占用原端口，所以只能另开一个入口。
插件端管理指令：/zstdnet status | reload | start | stop（需要 zstdnet.admin 权限，默认 OP）。

单机「对局域网开放」：

开放界面里会多出一个 Zstd 端口输入框。游戏端口通常留空就行（会自动跟随本次实际的 LAN 端口）；开放成功后聊天框会提示本次实际使用的 Zstd 端口，点一下可以复制，把「你的公网IP:Zstd端口」发给朋友即可。忘了端口就用 /zstdport show 查。

【常用配置】

服务端 config/zstdnet-server.properties（模组会自动维护这个文件，支持热重载）：

>>> 代码块
enabled=true                 开启 ZstdNet
auto_takeover=true           自动接管 server-port（推荐保持默认）
level=9                      压缩等级 1-22，常用 3~9，越高越省流量也越吃 CPU
chunk_cache=auto             区块引用缓存，默认开启
dictionary_auto=false        设成 true 即开启全自动字典，人多的服建议打开
transform=false              实体包流变换，实体多的服建议两端一起打开
premium_verification=auto    内置正版验证，默认跟随 server.properties 的 online-mode
voice_transport=tunnel       语音复用入口端口，对外只放行一个口

客户端 config/zstdnet-client.toml 里主要是 level（默认 3）、chunk_cache（默认开）、transform（默认关）这几项，默认值开箱可用，一般不用动。

完整配置项（限速、字典、LDM、真实 IP / PROXY protocol、语音端口、统计间隔等）见项目 README。

【指令】

>>> 代码块
/zstdhud [on|off|toggle]            开关游戏内 HUD（客户端指令）
/zstdport show                      查看当前端口（单机 / 局域网场景）
/zstdport zstd <端口>                手动指定 Zstd 端口
/zstdnet status|reload|start|stop   插件端管理指令（需要 zstdnet.admin）

【常见问题】

进不去服务器？

・auto_takeover=true 时，玩家填原来那个公网端口就行；只有改成 false 才需要填配置里的 listen 端口
・确认 FRP / 隧道转发到的是 listen 端口，而不是后端游戏端口
・确认 enabled=true，listen 和 target 没写反，Zstd 端口没被别的程序占用

压缩率接近 100%，是不是没生效？

不一定。有些流量本身就不适合再压缩，或者已经被加密，收益会明显下降。可以试试打开全自动字典（dictionary_auto=true）和实体包流变换（transform，两端都要开）。

连的服务器没装 ZstdNet 会怎样？

客户端默认 raw_fallback=true：点「加入服务器」时先做一次探测，对端不支持就自动改用原版直连进服，进服后聊天栏提示「本次连接未压缩」，不会卡在登录报错。

语音模组能用吗？

可以，而且是零配置的，mod 服和插件端都适用。语音流量不压缩、只做原样转发。唯一要注意的：别把 Simple Voice Chat 的 voice_host 或 Plasmo Voice 的 [host.public].ip 显式填成某个公网地址，否则客户端会按你填的地址直连、绕过 ZstdNet（服务端日志会打一条 WARN 提醒）。留默认（空 / 0.0.0.0）即可。

会不会和别的联机模组冲突？

有可能。如果多人游戏菜单或者「对局域网开放」界面被其他模组大幅改写，理论上仍存在兼容性风险。这种情况下用 /zstdport show 可以查到当前端口。

开了内置正版验证，原来的存档会丢吗？

被验证的玩家会改用正版 UUID，原来的离线 playerdata 不会自动迁移——这一点和任何「离线转在线」的切换是一样的，切换前请自行备份 / 迁移存档。
